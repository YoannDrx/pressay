# Feature ledger

Ce ledger est le registre de vérité produit. Un écran visible ou un type TypeScript ne suffit pas : chaque capacité doit relier l'interface au backend réel, couvrir ses erreurs et passer un test natif.

## Synthèse

| Domaine            | Conclusion                                                                                                                                                                                                                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dictée locale      | Pipeline substantiel, à vérifier nativement de bout en bout.                                                                                                                                                                                   |
| Modèles locaux     | Gestion complète ; routes de marque et fallback, tailles et SHA-256 complets des trois artefacts validés. La route de marque redirige encore vers Hugging Face ; redondance/cache et performances matérielles non validés.                     |
| Onboarding         | Flux Signal OS simplifié en trois étapes visibles — bienvenue, préparation et première dictée — avec permissions réunies, modèle recommandé et reprise des autorisations validée nativement.                                                   |
| Voice Bar/menu bar | État canonique, routes, erreurs, HUD Minimal/Live et panneau menu bar enrichi implémentés ; preuve native requise.                                                                                                                             |
| Productivité       | Surfaces et logique présentes ; guards Free/Pro backend centralisés, matrice native encore incomplète.                                                                                                                                         |
| Historique         | Chiffrement et rétention présents ; comportement natif et absence de fuite à éprouver.                                                                                                                                                         |
| BYOK               | Fournisseurs et Keychain présents ; contrats réels non validés.                                                                                                                                                                                |
| Compte/Cloud/sync  | OAuth 2.1 PKCE Google validé de bout en bout sur le site de production ; l'app expose désormais une phase de bootstrap distincte. Le callback app bêta.2, Apple, la production Cloud indépendante, la sync et la revue externe restent requis. |
| Paiement           | Le contrôle commercial est fermé sur la preview et aucun nouvel achat n'active d'essai. Le compte Stripe dédié, Test Clocks, fiscalité/live et StoreKit/TestFlight restent des release gates.                                                  |
| Distribution       | `v2.0.0-beta.3` directe signée, notarisée et staplée validée après retéléchargement ; bundle MAS sandboxé compilé en CI et signé localement avec son profil, mais non validé en Sandbox/TestFlight.                                            |

## Ce qui peut être annoncé aujourd'hui

Formulation sûre : « Pressay est conçu local-first et son pipeline de dictée locale est implémenté. »

Formulations prématurées : « fonctionne partout à 100 % », « paiement prêt », « sync auditée », « compatible Mac App Store » ou « tous les fournisseurs BYOK sont supportés ». Ces promesses exigent les gates indiqués ci-dessus.
